# Security and threat model

The operator, OMP runtime and operating-system account are trusted. Untrusted/accidental queue files, wrong-session requests, duplicate writers, uncertain API outcomes, process interruptions, stale locks and filesystem links are the threats addressed here. Prompts are task authority: only owner-approved prompts belong in a private plan. Schema validation is not a sandbox for arbitrary task instructions. OMP itself retains its configured tool/approval boundary.

No local HTTP server, remote listener, firewall rule, browser injection, platform-token retrieval or credential grant is included. The one thing that keeps running is the wake-up watchdog's per-user scheduled task: `pots install` creates it when Claude Code or Codex is found, it starts at log-in and then every 5 minutes, it can start Claude Code or Codex ([wake-up resume](docs/coordinator-resume.md)), and `pots uninstall` removes it. `pots install --no-coordinator-wakeups` removes it too, except when old wake-up files cannot be checked as Setup's own: then the task is left alone, the install says so, and it names how to stop it. The controller uses only filesystem and OMP extension APIs. OMP provider traffic remains OMP's responsibility. There are no npm dependencies or vendored SDKs. `setup` and `start` probe only `omp --version`; they never read tokens, start a login or claim provider access. `start --confirm-offline` runs OMP in the foreground after a manual offline-ownership confirmation; it cannot detect OMP instances that run without this bridge.

Use an owner-only local state directory and owner-only config/session files. Manual setup requests POSIX modes but does not set or verify a Windows DACL; verify its Windows permissions independently before real use. Automatic Windows setup applies and verifies current-user-only permissions and checks existing private state on reuse. The MCP adapter does not inspect ACLs and must not be advertised as doing so. Roots and ancestors reject linked paths, but same-account or administrator malicious writers and path replacement races are outside this boundary. Do not use shared/cloud-synced/network filesystems. Do not put the state directory in the public repository.

The public source contains only synthetic session IDs and example paths. `.gitignore` is a convenience, not a security boundary. Inspect every tracked file, scan secrets and identifiers, and inspect commit metadata before publication. Never publish mailbox records, real allowlists, session transcripts, task prompts, logs or model credentials. Receipts avoid raw content, but private plan files retain prompts; redact secrets before constructing a plan. Plans/receipts can disclose workflow metadata, so keep them private too.

At-most-one API invocation is conditional on an intact reservation journal and exclusive supervisor. It is not exactly-once delivery. User-record admission is not proof of provider execution; a terminal event is not proof of successful work. An interrupted operation ends failed and is never automatically resent. A malformed or inaccessible record stops the supervisor rather than permitting another side effect.

Abort only cancels future bridge steps. It is neither a process kill nor rollback of project effects. Deadlines bound queue submission authority; they cannot enforce how long an already executing OMP run or tool takes. Use safe task scope and OMP-native limits/interrupts as appropriate. No NAS/game/database mutation is part of fixture tests.

The optional stdio MCP adapter ([desktop adapter](docs/desktop.md)) listens on no network. Its client gets these capabilities over one pinned setup or a named registry: read status, add a one-prompt 24-hour plan under a caller-supplied UUID, read one receipt and cancel future steps (plus bounded lane status, lane-watcher lines and a director heartbeat). Enqueue is task authority, so its activation needs explicit owner approval. Configure per-call approval in the client, but do not infer enforcement from annotations; explicit user requests and observed host behavior must be assessed. Only registered connection names may be selected; arbitrary sessions, paths, continuation, review, lock recovery, launch and commands are not exposed; returned data excludes prompts, paths, session IDs and raw errors. Single mode pins its first valid setup identity. Named mode reads the local registry fresh on every call and verifies every selected setup against its captured identity; a changed identity is refused and needs offline review. An adapter that holds the controller credential also connects sessions saved after setup (at most every 30 seconds, only sessions not yet registered, never more than 64 in all); an adapter without the credential never connects anything by itself. There is no default target or broadcast. It relays receipt reasons only from the core's fixed reason codes and plans without receipts only when they pass the core plan rules for this session; anything else is refused. Tools are served only after the MCP initialize handshake completes. Input is consumed only while stdout drains and fewer than 16 operations are pending, so a non-reading client cannot make it act or buffer without bound. Remote API/MCP adapters additionally require a separate security review covering transport, authentication, narrowly scoped capabilities, expiry, replay protection, audit, revocation and whether prompts constitute acceptable authority. Approval to publish this source does not authorize activating any of these surfaces.

The install downloads no Node.js or OMP and adds no inbound listener. The one-line install and the optional updater ([updates](docs/update.md)) make outbound requests, through GitHub CLI only. It runs `gh` with fixed argument vectors for the repository `Jumpstile/pi-on-the-side` on `github.com`, without a shell (the pasted line names `github.com` itself, so a `GH_HOST` in your environment is never used, and the script forces `GH_HOST` for its own calls and puts your value back when it ends), prompts disabled, a timeout and capped output. It uses only the existing `gh` login and never reads, stores or passes credentials or starts a login. No repository, host, URL, mirror or authentication override exists. The release asset's GitHub `sha256` digest and declared size bind the downloaded bytes; this is integrity, not independent publisher authentication, and anyone able to publish releases there is trusted. Bundles must be exactly the runtime file set, in a strict stored-only ZIP (no links, traversal, duplicates or extras). Before activation, the bundle must satisfy the runtime's fixed package-metadata contract, including the Node engine field. A mismatch is refused before bundle code runs. This metadata check is separate from probing the currently selected OMP executable and its runtime capabilities. No hook or command runs before activation. Versions are immutable folders in a managed install, outside the checkout and state. Activation is an atomic pointer swap while holding an install lock (so two updates cannot run at once), with a backup of the old pointer; it is rolled back if a step fails and keeps the previous version for verified rollback. An open OMP session or a running plan does not block it: running sessions keep the version files they already loaded, and the next start uses the new version. The explicit `--confirm-offline` flag is the switch that performs an apply or rollback. A source checkout is never written. The desktop `.mcpb` contains no update code, and its tools grant no update authority.

To report a security concern privately, use the "Report a vulnerability" button on the Security tab of this repository and describe a minimal synthetic reproducer. Do not include credentials or private session artifacts in public issues. No bounty program is promised.

# Controller coordination

CLI/MCP enqueue, cancellation and review require a locally generated capability
that explicitly owns the target session. An exclusive filesystem gate serializes
those writes with ownership acquisition/handoff across processes. Reads stay
shared; crashed gates and lost credentials fail closed without timed takeover.
This is collision prevention for trusted same-user clients, not a sandbox or
defense against another process running as the Windows account. Sharing a key,
old advanced writers, direct Store calls, manual file edits and native OMP
commands can bypass this boundary. Stop old writers before rollout; never use
handoff to replay a failed or malformed plan. [Protocol and recovery](docs/controllers.md).
