# Contributing and tests

There is no installer program: the product is commands only (the one-line install and the `pots` commands). A release is three files: the update bundle `omp-session-bridge-<version>.zip` (built with `node scripts/pack-mcpb.mjs --release <absolute path>`), the Claude Desktop extension `omp-session-bridge-<version>.mcpb` (`node scripts/pack-mcpb.mjs <absolute path>`) and `scripts/install.ps1`. Keep outputs outside the checkout.

`test/install-output.test.mjs` covers `pots install` and `pots instructions`: the one-sentence result and its next step, input refusal and transcript non-disclosure, and that every next step is a command or a file. `test/pots.test.mjs` covers the `pots` commands (install, upgrade with a session open and with stable, prerelease or both published, a corrupt download, status, uninstall) against fake releases, and runs `scripts/install.ps1` against a fake `gh` (stable only, prerelease only, both, none). Attach `scripts/install.ps1` to every release: it is the one-line installer, and the paste line downloads it from the newest release. `test/package.test.mjs` checks the packed bundles. `scripts/pack-mcpb.mjs` builds the update bundle `omp-session-bridge-<version>.zip` that the bridge's own updater requires on a release (see the release checklist in `docs/update.md`). It contains no Node/OMP download or credentials. Existing automatic setup tests still cover current-user Windows ACLs, unchanged records/controllers and duplicate-process guards.

`test/controller.test.mjs` runs local Node children with deterministic
stdin/stdout barriers. It covers cross-process acquisition/write/handoff races,
crash-lock retention, CLI/MCP ownership, named-session isolation, same-name
clients with different capabilities, legacy refusal and unchanged unknown or
in-flight receipts across handoff. These tests never invoke OMP or a provider.

For a fresh-process crash/recovery smoke, run these commands as three separate Node invocations with the same **new disposable absolute root**:

```powershell
node scripts/restart-smoke.mjs prepare C:\BridgeFixtures\new-restart-fixture
node scripts/restart-smoke.mjs crash C:\BridgeFixtures\new-restart-fixture
node scripts/restart-smoke.mjs recover C:\BridgeFixtures\new-restart-fixture
```

The parent must already exist. This fixture uses a fake adapter and marked synthetic state only; `recover` removes only that fixture's exact crash lock. It must never be pointed at real runtime state. Keep the disposable fixture private and remove/archive it separately after inspection.

Use Node.js 22+ with no dependency install. Run `npm run check` and `npm test`. On Node 22 use `node --experimental-strip-types --test`; Node 22.23.3 does not support `--test-isolation=none`. On the tested Node 26 runtime that option can help with restricted test-process isolation; CLI, MCP stdio and packaging tests still need child processes. Tests create private disposable synthetic directories beneath the OS temp root and clean only those roots. They never read real provider credentials or owner session transcripts, start OMP, modify owner projects or access a network. Setup/start tests inject the host probe and launcher through the CLI module API; the `bin/` entry always uses the real PATH lookup, `--version` probe and foreground spawn, and no environment variable can attest the host. Packaging tests build `.mcpb` archives into temp folders outside the checkout and inspect them with an independent ZIP reader.

Model-helper fixtures require a neutral temporary root with no ancestor `.omp/config.yml`, `.omp/config.yaml` or `.omp/settings.json`. If normal TEMP/TMP contains such owner configuration, preserve it and select a fresh private per-process TEMP/TMP root outside that configured ancestry. Never remove or bypass the production neutral-scope guard to make a test pass. `node --test --test-concurrency=1 --test-timeout=120000` runs the same full suite with one test file at a time when concurrent local validation competes for resources.

Stdio child fixtures poll complete newline JSON frames within a bounded 20-second wall-clock deadline, retain every response/framing/non-disclosure assertion, and close only their own spawned child before deleting its disposable root. The failure-cleanup close wait is bounded to five seconds. These fixture bounds do not establish a product response-time guarantee or bound the existing normal successful shutdown wait.

Meaningful cases cover duplicate IDs and supervisors, exact session isolation, at-most-one sends, finite continuation, no false success, API acceptance then throw, unknown gating/review, shutdown/restart uncertainty, abort/expiry, mismatched/overlapping lifecycle, missing admission, persistence failures, concurrent ticks, links, exclusive publication and transcript admission spoofing/size/replacement; setup idempotence/refusal/no-overwrite and lock refusal; MCP initialize/initialized ordering, per-process session pinning, closed schemas, duplicate IDs, receipt-reason and plan-source recognition, redaction, stdout purity and stdio flow control under a non-reading client or oversized-frame flood. Add reproducing failure tests for changes to these boundaries.

Update tests (`test/update.test.mjs`) inject a synthetic GitHub CLI transport through the CLI module API. It serves local release metadata and bundles built by the real `--release` packer. No test contacts GitHub, needs a `gh` login or runs `gh`; the bounded child runner is exercised with Node itself. Cover the authority (fixed `gh` vectors, latest/pagination, repository/host checks, digest and size), bundle refusal (traversal, links, duplicates, extras), compatibility, the install lock (a second update defers; an open session or a queued plan never blocks one), source-checkout refusal, atomic activation and its failure/restore truth, unchanged state hashes and verified rollback.

Upgrade and zero-configuration tests build fake older installs in a disposable folder from the real runtime files and run the real installer over them: `test/upgrade.test.mjs` (older per-session `runtime\managed-<id>` layouts kept untouched, an unreadable managed folder, a running session that holds old files open, failure at each step, no-op re-run, rollback, uninstall of an upgraded install), `test/zero-config.test.mjs` (fake home and app folders: a fresh install and an upgrade end with every saved session connected, the local assistant registrations and the Claude skill in place and everything left for the user reported, re-running changes nothing, rollback restores only what Setup wrote, what no program can do is reported with its exact next step) and `test/clients.test.mjs` (the assistant connection module on its own). They never touch a real install, a real assistant app, the registry, a network or OMP. When a release changes the runtime file list, change `RELEASE_FILES` in `src/update.mjs` and `runtimeFiles` in `package.json` together; a test fails if they differ.

The production TypeScript adapter is driven by offline tests through runtime type stripping. A disposable OMP 18.7.0 RPC smoke additionally verifies the tested host path; other modes and owner-session activation need separate verification. The v0.2.9 candidate also passed a zero-prompt OMP 18.10.0 RPC smoke for extension loading, `/bridge` registration and synthetic session binding only; it did not verify a fresh supervisor/lock lifecycle, model turns or provider connectivity. Offline success cannot be promoted to a live integration result. A saved OMP session must not be duplicated to gain a test shortcut.

Keep source neutral and generic. No private IDs, real paths, runtime messages, logs or credentials in fixtures or docs. Use explicit file staging, a secret/identifier scan and diff review before any push. Preserve signing settings. No attribution trailers. An offline test pass verifies local protocol behavior under the modeled assumptions, not project task correctness or provider availability.
